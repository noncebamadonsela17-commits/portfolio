01 — AWS · Terraform

Hospital Occupancy Cloud

Files still reach the cloud when a clinic connection drops, and none are lost if processing is slow.

  • Designed an AWS landing zone in Cape Town, written entirely in Terraform, so clinics can upload patient-encounter files whenever they have power and a connection.
  • Added retry logic on the clinic side, plus versioned S3 and an SQS queue with a dead-letter queue so files are not lost if processing is slow.
  • Applied least-privilege IAM, CloudWatch alarms, and an AWS Budget, and wrote the runbook for deployment and failure drills.

Failed uploads. The clinic script retries when the connection drops. S3 keeps versions of the file. SQS holds the message, and a dead-letter queue catches it if processing fails, so a slow step does not delete the data.

02 — Data pipeline

Bed Occupancy Forecasting Pipeline

Each ward gets a daily occupancy figure, a 7-day forecast, and an alert above 90% capacity. The patient-stay records are synthetic.

  • Built a daily batch pipeline that turns synthetic patient-stay records into occupancy per department, in bronze, silver, and gold layers.
  • Ran PostgreSQL in Docker Compose, with pandas and dbt for transforms and an Airflow DAG for the schedule.
  • Added a Prophet forecast and a Streamlit dashboard that flags wards above 90% capacity. pytest runs in GitHub Actions on Python 3.10 and 3.11.
